## 🖥️ 1. Entenda o que aparece na tela

| Elemento | Como interpretar |
| :--- | :--- |
| Repositório | o conjunto de pastas, arquivos e histórico do projeto |
| Pasta | um agrupamento de materiais sobre uma área ou entrega |
| `README.md` | a página de apresentação da pasta; costuma aparecer ao abri-la |
| Arquivo `.md` | documento de texto formatado, com títulos, tabelas e links |
| Branch | uma linha de trabalho em que se pode propor uma alteração |
| Commit | um registro de alteração com autor e mensagem |
| Pull request, ou PR | uma proposta de mudança que a equipe pode revisar |

Para ler os materiais, basta abrir os links. Para editar ou revisar propostas no GitHub, você precisará de conta e das permissões correspondentes.

## 🗄️ 4. Por que alguns dados não aparecem no GitHub?

Os arquivos brutos do data room permanecem locais e estão protegidos pelo `.gitignore`. O repositório compartilha documentação, código e resultados agregados. O [catálogo dos Exhibits](../../documentos/exhibits-m2/README.md) explica a organização local.

Se um PDF estiver listado no catálogo, você poderá abri-lo no repositório publicado quando ele tiver sido incluído. Arquivo existente na máquina e arquivo disponível online são situações diferentes.

## 🔍 5. Como ler resultados sem confundir os estágios

- **Fonte oficial:** informação presente no enunciado, dicionário ou material de aula.
- **Hipótese:** explicação que será colocada à prova.
- **Evidência observada:** resultado calculado, acompanhado de fonte e método.
- **Recomendação:** ação proposta a partir da evidência, com limitações.

“Vamos treinar um modelo” descreve uma tarefa. “O modelo atingiu determinada métrica” exige execução e validação. Essa diferença ajuda a revisar os documentos mesmo sem conhecer o código.

Você pode melhorar uma hipótese, conferir uma conta, revisar a interpretação de um gráfico, rotular uma amostra de texto ou verificar se uma recomendação respeita o orçamento. Uma contribuição útil deixa claro o que mudou e por quê.
